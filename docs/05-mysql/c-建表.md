# 表操作

表是数据存储的基本单位。

![](https://raw.githubusercontent.com/hughxusu/lesson-knowledge/develop/images/mysql/component-of-a-database-table.gif)

* 行（Row/Record/Tuple）：表中的一条具体记录，即一条数据。
* 列（Column/Field/Attribute）：表中的一个字段，定义了数据的类型和属性。

查询当前数据库所有表

```sql
show tables;
```

## 创建表

使用`create`命令可以创建一张表

```sql
create table users(
    id int comment 'ID',
    name varchar(50) comment '用户名',
    gender varchar(1) comment '性别'
) comment '用户';
```

* `table users`表示创建一个用户表。
* `id`表示字段名；`int`表示字段类型；`comment 'ID'`字段注释，可选参数；
* 不同的字段之间，用`,`分开。

### 查看指定表结构

使用`desc`命令，可以查看到指定表的字段，字段的类型、是否可以为NULL，是否存在默认值等信息。

```sql
desc users;
```

### 查询建表语句

查看建表语句的，可以查询建表时的默认值，如：存储引擎、字符集等。

```sql
show create table users;
```

## 数据类型

在前面创建表语句中，用到了`int`和`varchar`来定义数据类型。除此之外，在MySQL中还有多种其它的数据类型。MySQL的数据类型，主要分为三类：数值类型、字符串类型、日期时间类型。

### 数值类型

| 类型        | 大小 (bytes) | 有符号(SIGNED)范围             | 无符号(UNSIGNED)范围               |
| ----------- | ------------ | ------------------------------ | ---------------------------------- |
| TINYINT     | 1            | `(-128，127)`                  | `(0，255)`                         |
| SMALLINT    | 2            | `(-32768，32767)`              | `(0，65535)`                       |
| MEDIUMINT   | 3            | `(-8388608，8388607) `         | `(0，16777215)`                    |
| INT/INTEGER | 4            | `(-2147483648， 2147483647)`   | `(0，4294967295)`                  |
| BIGINT      | 8            | `(-2^63，2^63-1)`              | `(0，2^64-1)`                      |
| FLOAT       | 4            | `(-3.402 E+38， 3.402 E+38)`   | `0 `和`(1.175 E- 38，3.402 E+38)`  |
| DOUBLE      | 8            | `(-1.798 E+308， 1.798 E+308)` | `0`和`(2.225 E-308， 1.798 E+308)` |
| DECIMAL     |              | 依赖于M（精度）和D（标度）的值 | 依赖于M（精度）和D（标度）的值     |

* 年龄：不会出现负数，且范围有限，可以使用`age tinyint unsigned`。
* 分数：`score float(4, 1)`，单进度浮点。显示4位数字，最多出现一位小数。

> [!warning]
>
> `score float(4, 1)`只表示显示时的精度，但实际存储仍然是标准的单精度浮点数，范围巨大。

* `DECIMAL`用于存储精确数值的数据类型，特别适合财务、货币等需要精确计算的场景。

```sql
# DECIMAL(M, D)
DECIMAL(5, 2) # 总位数5，其中整数部分最多3位，小数部分2位，有效数字范围：-999.99 到 999.99
DECIMAL(3, 0) # 总位数3，没有小数部分，有效数字范围：-999 到 999
```

* M（Precision-精度）：总位数，范围1~65。
* D（Scale-标度）：小数位数，范围0~30，且D≤M。

| 特性     | `FLOAT(4,1)`                         | `DECIMAL(4,1)`                 |
| :------- | :----------------------------------- | :----------------------------- |
| 存储类型 | 浮点数（近似值）                     | 定点数（精确值）               |
| 精度保证 | 不保证精确，有精度误差               | 绝对精确，无精度误差           |
| 内部存储 | 二进制浮点                           | 十进制字符串打包存储           |
| 计算速度 | 快（硬件支持）                       | 慢（软件实现）                 |
| 存储空间 | 固定4字节                            | 可变（根据M决定）              |
| 范围大小 | 非常大（约±3.4e38）                  | 受M限制（-999.9到999.9）       |
| 适用场景 | 科学计算、统计、不需要绝对精确的场景 | 财务、货币、需要绝对精确的场景 |

### 字符串类型

| 类型       | 大小                  | 描述                         |
| ---------- | --------------------- | ---------------------------- |
| CHAR       | 0-255 bytes           | 定长字符串（需要指定长度)）  |
| VARCHAR    | 0-65535 bytes         | 变长字符串（需要指定长度）   |
| TINYBLOB   | 0-255 bytes           | 不超过255个字符的二进制数据  |
| TINYTEXT   | 0-255 bytes           | 短文本字符串                 |
| BLOB       | 0-65 535 bytes        | 二进制形式的长文本数据       |
| TEXT       | 0-65 535 bytes        | 长文本数据                   |
| MEDIUMBLOB | 0-16 777 215 bytes    | 二进制形式的中等长度文本数据 |
| MEDIUMTEXT | 0-16 777 215 bytes    | 中等长度文本数据             |
| LONGBLOB   | 0-4 294 967 295 bytes | 二进制形式的极大文本数据     |
| LONGTEXT   | 0-4 294 967 295 bytes | 极大文本数据                 |

* `char`是定长字符串，指定长度多长，就占用多少个字符，如果长度不够，会用空格补充。
* `varchar`是变长字符串，指定的长度为最大占用长度。
* 实例
  * `username varchar(50)`用户名长度不定，但最长不会超过50个字符。
  * `gender char(1)`性别男或女，只要一个字符。
  * `phone char(11)`手机号，固定一个字符。

> [!note]
>
> 数据类型的选择，在够用的前提下，越小越好，这样可以更多的节省存储空间。

### 日期时间类型

| 类型      | 大 小 | 范围                                       | 格式                  | 描述       |
| --------- | ----- | ------------------------------------------ | --------------------- | ---------- |
| DATE      | 3     | 1000-01-01<br>9999-12-31                   | `YYYY-MM-DD `         | 日期       |
| TIME      | 3     | -838:59:59<br>838:59:59                    | `HH:MM:SS`            | 时间       |
| YEAR      | 1     | 1901<br>2155                               | `YYYY`                | 年份       |
| DATETIME  | 8     | 1000-01-01 00:00:00<br>9999-12-31 23:59:59 | `YYYY-MM-DD HH:MM:SS` | 日期与时间 |
| TIMESTAMP | 4     | 1970-01-01 00:00:01<br>2038-01-19 03:14:07 | `YYYY-MM-DD HH:MM:SS` | 时间戳     |

* 实例：`birthday datetime`生日，记录出生年月，可以用来计算年龄。

### 其他数据类型

* `BIT(M)`位数据类型，用于存储位二进制值，`M`表示位数，范围1-64，默认1。
* `ENUM`枚举类型，用于存储单一值，可以选择一个预定义的集合。
* `SET`集合类型，用于存储多个值，可以选择多个预定义的集合。
* `json`数据类型。从MySQL 5.7.8+就开始支持JSON数据类型，到MySQL 8.0以后更是增强了JSON功能的支持。

> [!warning]
>
> 对于图片、音频、视频等文件，不存储在数据库中，而是上传到某个服务器上，然后在表中存储这个文件的保存路径。

## 约束

约束是作用于表中字段上的规则，用于限制存储在表中的数据。以保证数据库中数据的正确性、有效性和完整性。常见的几种约束

| 关键字        | 名称                   | 描述                                           |
| ------------- | ---------------------- | ---------------------------------------------- |
| `NOT NULL`    | 非空约                 | 限制该字段的数据不能为空                       |
| `UNIQUE`      | 唯一约束               | 保证该字段的所有数据都是唯一的                 |
| `PRIMARY KEY` | 主键约束               | 主键是一行数据的唯一标识，要求非空且唯一       |
| `DEFAULT`     | 默认约束               | 保存数据时，如果未指定该字段的值，则采用默认值 |
| `CHECK`       | 检查约束（8.0.16之后） | 保证字段值满足某一个条件                       |
| `FOREIGN KEY` | 外键约束               | 用来让两张表的数据之间建立连接，保证数据的一致 |

## 修改表

使用`alter table`可以实现对表的修改操作

### 添加字段

```sql
alter table users add phone char(11) comment '手机号' unique;
```

* `users`表名。
* `add`关键字，表示添加。
* `phone`字段名称。
* `char(11)`数据类型。
* `comment '手机号'`注释。
* `unique`约束条件。

### 修改数据类型

```sql
alter table users modify id bigint unsigned primary key auto_increment;
```

* `modify`关键字，表示修改。
* `id`字段名称
* `bigint unsigned`修改后的数据类型。
* `primary key`修改后的约束。
* `auto_increment`数据自动增长。

> [!note]
>
> `auto_increment`是列属性，每当添加新的数据时，自动增长。

### 修改字段名和字段类型

```sql
alter table users change name nickname varchar(30) comment '昵称';
```

* `change`关键字，表示更新。
* `name`旧列名。
* `nickname`新列名。
* `varchar(30)`数据类型

| 特性     | `CHANGE`                 | `MODIFY`           |
| :------- | :----------------------- | :----------------- |
| 主要功能 | 可以修改**列名和列定义** | 只能修改**列定义** |
| 列名修改 | ✅ 支持                   | ❌ 不支持           |
| 语法     | 需要指定**新旧列名**     | 只需要**列名**     |
| 标准     | MySQL特有                | 标准SQL            |
| 使用     | 需要改列名时使用         | 只改定义时使用     |

### 删除字段

```sql
alter table users drop gender;
```

* `drop`关键字，删除。
* `gender`字段名称。

### 修改表名

```sql
alter table users rename to music_users;
```

* `rename to`关键字，表示重命名。
* `music_users`新表名。

### 删除表

```sql
drop table if exists music_users;
```

* `drop table`关键字，删除表。

> [!alert]
>
> 在删除表的时候，表中的全部数据也都会被删除。

## 表操作的注意事项

### 字段操作顺序

在表创建和修改时，字段操作遵循一定的顺序

```sql
id                    # 字段名称
BIGINT UNSIGNED       # 1. 数据类型
NOT NULL              # 2. NULL属性
DEFAULT 1             # 3. 默认值
AUTO_INCREMENT        # 4. 自增
PRIMARY KEY           # 5. 键约束
COMMENT '主键ID'       # 6. 注释
```

> [!warning]
>
> 部分属性顺序调整语句仍然可以执行，但上面的顺序表操作的推荐顺序，表的修改和创建都成立。

字符串操作增加了字符集操作

```sql
username 
VARCHAR(50)                  # 1. 数据类型
CHARACTER SET utf8mb4        # 2. 字符集在类型后
COLLATE utf8mb4_unicode_ci   # 3. 排序规则
NOT NULL
DEFAULT ''
COMMENT '用户名',
```

### SQL的设计哲学

> [!think]
>
> 从上面的语句中可以观察到什么现象？

SQL语言的特点：

1. 动词先行：SQL语句总是以动词开头，这种设计哲学强调了意图的优先级。
2. 动词+对象+条件（限定词）：语法顺序极其接近英语。

SQL的设计哲学被称为“声明式编程”，SQL侧重于告诉计算机需要什么。像Python等编程语言，称为过“过程式”语言，告诉计算机怎么做。

| 概念 | 词性分类   | 核心关键字示例                | 作用                                                         |
| ---- | ---------- | ----------------------------- | ------------------------------------------------------------ |
| 操作 | 动词       | `DELETE`, `CREATE`, `ALTER`等 | 发起意图：决定对系统执行什么指令。                           |
| 对象 | 名词       | `DATABASE`, `TABLE`等         | 操作载体：动词作用的目标。包括：实体、容器、数据元           |
| 限定 | 介词、连词 | `FROM`, `WHERE`等             | 逻辑约束：定义动作发生的“范围”、“条件”和“关联方式”。         |
| 修饰 | 形容词     | `UNIQUE`, `PRIMARY`等         | 属性描述：描述对象或数据的特质，定义数据的约束、唯一性等规则。 |

> [!note]
>
> SQL语言操作数据库的步骤：
>
> 1. 先定动作。
> 2. 再找目标。
> 3. 最后细化范围。
